# Claude Session Desk

Windows 上的 Claude Code 会话工作台。[GitHub 仓库](https://github.com/wj497840823/claude-session-desk) · [下载 Releases](https://github.com/wj497840823/claude-session-desk/releases)。应用内名称为“Claude 会话管理器”。

一个 Windows 桌面应用，用来浏览、搜索和管理本机 Claude Code 的历史会话，并可以直接在应用内与 Claude 对话，或一键在新终端中 `claude --resume` 回到原会话。

这是独立开发的非官方工具。运行真实对话需要自行安装并登录 Claude Code CLI，项目不包含该 CLI 或任何登录凭据。

支持项目展开与会话定位、多个对话标签、搜索收藏、截图/文件附件，以及核验后的本机文件打开与定位。

开源许可：[MIT](LICENSE)。开发协作见 [CONTRIBUTING.md](CONTRIBUTING.md)，首次上传和 EXE 发布见 [GitHub 发布指南](docs/github-publishing.md)。

## 直接使用

当前版本为 **1.1.3 重新打包版**，包含文件链接核验与短文件名定位修复，以及活动会话默认收起、文件复制粘贴和附件草稿功能。

发布的 EXE 请从 [Releases 页面](https://github.com/wj497840823/claude-session-desk/releases) 下载。本地构建输出为：

```
便携版：dist/ClaudeSessionManager-1.1.3-portable.exe
安装包：dist/ClaudeSessionManager-1.1.3-setup.exe
```

安装包按当前用户安装，可选择安装目录，并创建开始菜单和桌面快捷方式。便携版双击即可运行，无需安装。首次运行 Windows 可能提示 SmartScreen（未签名应用），选择「更多信息 → 仍要运行」即可。

## 1.1.3 重新打包：文件链接识别与定位

当前 1.1.3 便携版和安装版包含本节修复，已替换旧的同名发布文件；请使用新的 SHA256 校验值区分。

- 会话记录和实时终端先核验本机文件，再提供点击；方法名、字段、远程 Linux 路径、不存在的示例文件不再触发本地文件打开。终端原有蓝色语法配色保留。
- 短文件名和缩短的源码路径可在项目子目录中定位，只有唯一匹配时才可打开；重名时使用完整路径，避免误开其他模块的文件。
- 修复 Java 行号范围、带空格的 Windows 路径、换行补白导致路径损坏，并统一核验终端自带的文件超链接。
- 文件核验采用批量请求与有界项目索引，保留项目范围及符号链接检查。切换标签定位较早会话时也适配异步布局。

## 1.1.2：文件粘贴、附件草稿与导航收起

本节修改包含在 1.1.2 中，旧版 1.1.1 EXE 不包含以下调整。

- 在资源管理器复制文件或图片后，可在运行中的对话按 Ctrl+V、Shift+Insert 或点击粘贴按钮添加；截图、选择文件和拖放也使用相同的附件草稿。

- 顶部新建对话优先使用当前浏览的项目；修复窄窗口标题被挤断、附件过多时“清空记录”不可见，以及切换标签后残留拖放遮罩/菜单的问题。

## 设置

点击顶栏右侧的齿轮图标打开设置：

- **加载历史记录**：默认关闭。关闭时不读取 `~/.claude/history.jsonl`，左栏不显示历史记录区，搜索也不包含历史提示；开启并保存后才会加载。该设置不会删除任何 Claude 数据。
- **关闭窗口时隐藏到托盘**：默认开启。开启后，点 × 会隐藏到系统托盘；关闭此项则关闭窗口会直接退出。最小化保留任务栏图标。
- **主题**：跟随系统 / 浅色 / 深色。
- **点击活动会话时**：直接继续对话（默认）/ 先查看会话记录。
- **新建对话的默认权限模式**：新建对话时启动框的默认选项。
- **终端字号**：应用到新开和已打开的终端。
- **Claude 数据目录**：显示当前扫描路径，可点「重新扫描」。

## 后台运行与托盘

- 点击窗口右上角 `×` 时，可按设置隐藏到系统托盘，程序继续运行。最小化保留任务栏图标，可直接点击恢复。
- 正在运行的 Claude 对话不会因为隐藏窗口而中断。
- 点击托盘图标或再次启动程序可以恢复窗口。
- 说明：安装版重复启动会恢复已有窗口；便携版由于 electron-builder 启动器的限制，重复双击可能不会唤起已隐藏实例，此时请点击托盘图标恢复。
- 托盘菜单提供「显示主窗口」和「退出」；只有选择「退出」才会真正结束程序并终止终端会话。
- 程序使用单实例：重复启动会恢复已存在的窗口，而不是再开一个实例。

- 服务运行期间监听数据目录，会话变化后自动刷新
- 跟随系统深浅色

## 会话保留与历史记录

Claude Code 默认只保留 **30 天**的会话 transcript（`cleanupPeriodDays` 默认 30）。超过保留期的 `.jsonl` 会被自动删除，但 `~/.claude/history.jsonl` 中的提示词记录不会删除。

本机当前数量以应用顶栏为准；最近一次扫描约为：

- 12 个可恢复的完整会话（transcript）
- 204 个仅提示历史的会话（完整对话已被清理）

历史记录默认不加载，所以首次打开只显示 12 个活动会话；在设置中开启「加载历史记录」后才会显示历史区和历史搜索结果。

应用把两类会话分开显示：

- 「活动会话」和「项目」只包含 12 个完整会话，可以查看助手回复、工具调用，并「在终端恢复」。
- 开启历史记录后，底部「历史记录」默认折叠，包含当前所有仅历史会话；标记为「已清理」，可以查看提示词和当时粘贴的文本，但不能恢复或导出完整对话。
- 活动项目如果有历史记录，项目名旁会显示 `+N`；项目列表头的「历史 N」可以只查看该项目的已清理会话。
- 顶栏显示实际的活动会话数和历史条数，避免历史记录干扰日常操作。

### 删除历史记录

历史会话没有完整 transcript，删除的实际是 `~/.claude/history.jsonl` 中对应 sessionId 的提示记录：

- 详情页「删除历史记录」：删除单个历史会话。
- 列表勾选多条，或勾选「全选」后点「删除选中」：批量删除。
- 删除前会自动创建备份：`~/.claude/history.jsonl.bak-<时间戳>`。
- 删除后对应提示记录会从 Claude Code 的历史中消失，且无法通过本应用恢复；收藏中的对应会话也会一并移除。
- 如果 `history.jsonl` 正在被 Claude Code 写入，应用会检测到变化并要求重试，避免覆盖新写入的内容。

为避免以后继续丢失，本机 `~/.claude/settings.json` 已加入：

```json
"cleanupPeriodDays": 3650
```

修改前已备份为 `~/.claude/settings.json.bak-<时间戳>`。该设置只影响未来清理，已经删除的 transcript 无法通过本应用恢复。

## 应用内对话

右侧工作是标签式工作台，每个标签运行独立的真实 Claude Code CLI（xterm.js + node-pty），因此可以同时保留多个对话，不需要关闭已有对话再开新的。

- **点击活动会话**默认直接在右侧工作区恢复对话，不再需要先看记录再点「在应用内对话」；如果该会话终端已打开，会直接切过去。可在设置中改为「先查看会话记录」。
- **会话记录**标签：默认不显示；从终端「会话操作」菜单选择「查看会话记录」时打开，可点标签上的 × 关闭。用于查看 Markdown 记录、工具调用和导出。
- **对话**标签：每个实时 Claude 终端一个标签，可切换、关闭；关闭运行中的标签会确认。
- **终端标签菜单**保留会话操作：查看会话记录、在终端中恢复、导出 Markdown、在项目中打开、删除会话。
- **终端右上「Claude 功能」菜单**：
  - **回退到节点**：执行 `/rewind`，打开 Claude 原生回退选择器（需会话已有 checkpoint）；可选择恢复代码、恢复对话或两者。
  - **Skill 管理**：执行 `/skills`，打开 Skill 可见性/上下文管理列表（搜索、开关、排序）。
  - **MCP 管理**：执行 `/mcp`，打开 MCP server 管理界面，可查看/认证/启停服务器。MCP 工具仍由 Claude 按对话内容调用。
- **新建对话**：活动会话详情 →「在应用内对话」；活动项目行/列表头 →「新建对话」；项目标题旁 `+` → 选择文件夹新建项目。都会在当前右侧工作区新增终端标签。
- 左侧项目栏可通过顶栏按钮收起，右侧工作台会自动扩展。
- 没有会话和终端时，右侧显示新建对话入口，不再是空白区域。

## 资源占用优化

- 窗口隐藏到托盘或最小化时暂停会话扫描，恢复窗口时只刷新一次。
- 文件监听去抖为 1.2 秒，重复的刷新请求会合并，避免并发全量扫描。
- 元数据缓存只在会话文件真的变化时写回 `cache.json`；历史记录解析按文件 mtime/size 复用。
- 自动继续对话时不再后台加载 Markdown 详情，只有打开「会话记录」才解析。

启动前可选择权限模式：

- 跟随 Claude 设置（默认）
- `manual`：逐次询问
- `auto`：自动判断
- `acceptEdits`：自动接受编辑
- `plan`：计划模式
- `dontAsk`：不询问

终端会填满右侧工作区高度；Shift+Tab 可切换权限模式。关闭或结束运行中的对话前会确认；Claude 已写入磁盘的会话不会因关闭终端而丢失。

应用会移除 Electron 默认菜单，避免 Ctrl+R / Ctrl+W 被应用拦截；终端聚焦时 Ctrl+K 也不会抢走焦点。Ctrl+Shift+C 复制选中文本，Ctrl+V 粘贴。

为修复中文输入法候选窗落在终端右下角的问题，内嵌终端启动 Claude 时设置 `CLAUDE_CODE_NATIVE_CURSOR=1`，让真实终端光标跟随输入位置。Claude 默认的模拟光标会把真实光标留在状态栏右侧，仅升级 xterm 无法解决这个位置偏差。终端同时保留 `@xterm/xterm@6.1.0-beta.337` 的 IME 定位修复（#5759 / #5734），在开始组合输入前同步隐藏输入框。更新后需要重新打开应用内对话标签，让新的启动环境生效。

### 实现说明

- 终端服务不再限制为 8 个独立 PTY；每个标签有独立的 xterm 实例和进程，切换标签不会终止其他对话。
- 终端环境会移除父 Claude 会话的 `CLAUDE_CODE_CHILD_SESSION` 等标记，并设置 `CLAUDE_CODE_FORCE_SESSION_PERSISTENCE=1`，确保嵌入的 CLI 正常保存 transcript。
- 会尽量自动发现 Git Bash 并传给 Claude，避免 Windows 下 SessionStart hooks 找不到 bash。
- 关闭终端时使用 `taskkill /T /F` 终止完整进程树，避免 node-pty 的 ConPTY 清理助手在 TUI 进程上崩溃。
- 打包时使用 node-pty 的预编译 N-API 模块（`npmRebuild: false`），并把 `node-pty` 解包到 `app.asar.unpacked`。

## 恢复会话

点击「在终端恢复」后，应用会：

1. 在会话对应的项目目录打开新的命令提示符窗口；
2. 执行 `claude --resume <sessionId>`。

前提是本机已安装并登录 Claude Code CLI。应用会优先使用：

- 环境变量 `CLAUDE_CLI_PATH`；
- `%USERPROFILE%\.local\bin\claude.exe`；
- 否则回退到 PATH 中的 `claude`。

## Claude CLI 启动失败排查

如果应用内终端提示 `启动 Claude 终端失败：Cannot create process, error code: 2`，通常是 Windows 找不到 Claude Code CLI，常见原因：

- Claude Code 只安装在 WSL 中：Windows 应用无法直接使用，需要在当前 Windows 用户下安装 Windows 版。
- Claude Code 通过 npm 安装：实际入口是 `%APPDATA%\npm\claude.cmd`。1.0.11 起会自动解析 `.cmd/.bat` 并通过 `cmd.exe` 启动。
- 安装在非标准目录：设置环境变量 `CLAUDE_CLI_PATH` 指向 `claude.exe` 或 `claude.cmd` 的完整路径，然后重新启动应用。

验证方法：在 Windows 命令提示符执行 `claude --version` 能正常输出，应用内终端才能启动。

## 数据与安全

- 应用会读取 Claude 会话文件，并执行两类删除：
  - 活动会话：`.jsonl` 及附属目录移入系统回收站。
  - 历史记录：先从 `~/.claude/history.jsonl` 自动备份，再移除对应 sessionId 的提示行。
- 收藏和元信息缓存在 `%APPDATA%\claude-session-manager\`，不会修改 Claude 会话内容。
- 删除只影响选中的 `.jsonl` 及同名附属目录（`subagents/`、`tool-results/`）。
- 工具输出的完整内容若被 Claude 外部化保存，应用只提供「打开完整输出」，不会自动读取。

## 开发

环境：Node 24+、Windows。

```powershell
npm ci
npm run dev        # 开发模式
npm test           # 单元测试
npm run typecheck  # 类型检查
npm run build      # 构建到 out/
npm run package    # 打包便携版、NSIS 安装包和 ZIP 到 dist/
```

首次安装 Electron 时若下载失败，可使用镜像：

```powershell
$env:ELECTRON_MIRROR = 'https://npmmirror.com/mirrors/electron/'
npm ci
```

下载 Electron 二进制：

```bash
node node_modules/electron/install.js
```

## 测试用数据目录

可以临时指定其他 Claude 数据根目录，避免触碰真实历史：

```powershell
$env:CLAUDE_SESSION_MANAGER_ROOT = 'E:/temp/claude-projects'
npm run dev
```

## 已知限制

- 仅历史会话没有完整对话，无法恢复或导出完整内容。
- 应用内对话不默认提供 `bypassPermissions`（跳过所有权限）；具体工具授权使用 Claude 原生提示和 `/permissions`。
- 如果 Claude 的 fullscreen TUI 在 xterm 中启动失败，CLI 会回退到 classic renderer；功能不受影响。
- 便携版只包含 Windows x64 的 node-pty 原生模块。
- 不展示子代理（subagent）会话；它们随主会话一起保留/删除。
- Claude Code 的本地 JSONL 格式属于内部实现，未来版本若改变字段，应用需要相应调整。
- 不做代码签名和自动更新；安装包按当前用户安装，可选择安装目录。
- 超大工具结果只展示截断后的预览。
